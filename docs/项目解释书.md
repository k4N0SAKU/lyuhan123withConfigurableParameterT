## 一、总体方案与信任/架构边界

### 1.1 题面要求与业务痛点

题面（A1-22）六条要求：①多方密文推理、输入不出本地；②参与方认证、密文完整性校验、会话密钥生成/分发/更新/销毁全生命周期；③建立威胁模型，抵御窃听/中间人/推理结果篡改/重放/部分参与方合谋五类攻击；④输出四项资源指标（代码规模/内存/单轮耗时/网络开销）；⑤在安全假设下抵抗至多 t 个参与方合谋，保证输入与中间计算状态机密性；⑥业务痛点 + 同类方案对比 + 复现 + 创新点。

业务痛点（docs/00 §1）：政务热线与企业工单的敏感文本需要大模型做情绪研判/分类定级，但《个人信息保护法》与内控合规禁止明文出域——"不用大模型，工单堆压；用了，隐私裸奔"。三个硬约束：**可用不可见**、**资源可落地**（普通 CPU 服务器）、**商用密码合规**（身份与传输必须国密）。

### 1.2 参与方总表（"手里有什么、永远看不到什么"）

| 角色 | 手里有什么 | 永远看不到什么 |
|---|---|---|
| **P0 客户端**（数据属主，信任根） | 明文输入/输出、CKKS 私钥（经白名单门控使用）、解密白名单 | ——（明文在出自己手之前已加密） |
| **P1 锚点**（计算方 1） | 掩码解密值 y=x+Σr（OTP 域）、自己的掩码片 r₁/s₁、结果分享 a₁ | 任何明文、任何 CKKS 私钥材料、他方掩码片 |
| **P2 合成方**（计算方 2） | CKKS 密文、OTP 值 w=v+Σs、自己的掩码片、密文域合成能力 | 任何明文、任何私钥材料 |
| **P3..Pm 计算方** | 密文/分享、自己的掩码片 | 同上 |
| **离线 CA** | 根私钥（签发证书）、CKKS 密钥分发（公钥全计算方、私钥仅 P0） | 不参与推理、不接触业务数据 |
| **恶意网络敌手** | 全部线缆字节（SM4-GCM 密文帧 + 握手期签名帧） | 任何会话密钥（SM2DH 协商 + ratchet 前向轮换） |

### 1.3 核心约束 → 设计映射

1. **输入不出本地** → 输入仅在 P0 本地 CKKS 加密，密文与 m-of-m 分享在计算方间流转；
2. **中间状态机密** → 每层转换点用 m 片掩码 OTP 遮蔽（§3.1）；不足 t+1 方的任何视角全是均匀随机；
3. **认证/完整性/密钥全生命周期** → X.509v3（演示级）+ SM2 挑战响应双向认证；SM2DH 会话密钥（GB/T 32918.3）；SM4-GCM 通道（RFC 8998 向量锚定）；ratchet 前向轮换；SM3 审计哈希链；两遍覆写销毁（§3.4）；
4. **五类攻击抵御** → 威胁模型（docs/02：敌手表 A1~A5、假设核对表 A-1~A-9、半诚实参与方+恶意网络）+ 自动化攻击套件（§3.5）；
5. **t 合谋抵抗** → D5′ m 片掩码协议族，t = m−1（§3.1）；
6. **资源可落地** → 全栈 CPU-only 实测，四项资源指标逐项申报（§7.1）。

### 1.4 关键设计决策的论证（含上限，如实）

- **为什么"CKKS 线性 + MPC 非线性"混合**：Transformer 线性层（QKV/FFN）是矩阵乘，同态加密+槽打包高效；GELU/Softmax 是非线性，同态算深度爆炸，放进秘密分享域用 Beaver 乘法。两条题面路线的取舍：**模式 A**（纯同态全密文）需要 84 层乘法深度（docs/01 §5.3：mode-a-THEORETICAL 2^17/链 3480bit），本栈 SEAL 对 n≥2^16 一律拒绝（TC128 安全表止于 N=32768/882bit，实测决策记录），**不可实例化**——理论推演保留，需 OpenFHE 级后端；**模式 B**（混合）乘法深度 2 层（同态分段+转换刷新），2^15 可用，为主线。
- **为什么门限口径是"计算参与方 t=m−1"而非"全体参与方"**：CKKS 私钥只有 P0 持有。P0 与任一计算方合谋 = 全钥+密文 ⇒ 中间态可解（docs/02 §3.3 登记）。把 P0 纳入门限需 CKKS 密钥门限化，撞两堵墙：①评审键（relinearization key）的 s² 交叉项不可按份额聚合；②门限部分解密需噪声泛洪（noise flooding）防密钥份额经多次样本累积求解，而转换协议要求 y **精确整数回收**（OTP 剥离）——泛洪噪声破坏精确性，互斥（docs/02 附录 A.4）。故 **P0=信任根是模型性假设**（客户端辅助 MPC 的标准模型），如实申报而非隐藏（§八）。
- **为什么 t = m−1 是隐私上限**：m-of-m 加性分享下，任意 m−1 方份额之和 = 真值 − 一份均匀随机数——缺的那片把真值完全遮住；m 方全合谋必然重构（分享的定义）。固定 m 下不存在突破 m−1 的协议技巧；要更大 t 只能加计算方。
- **为什么加性 m-of-m 而非 Shamir (k,n)**：Shamir 需域上拉格朗日插值，分享域是环 Z_{2^64}（2 无逆元，非域），做 Shamir 需扩域或双分享（域论代价）；加性 m-of-m 纯环上加法。代价：**零容错**（缺一方协议停滞，无 k<n 冗余）——登记为边界（§八）。
- **为什么解密白名单收口 P0（P1-R1 修订）**：P0 是唯一钥持者，若可任意解密则"中间状态机密"对 P0 无意义；白名单把合法解密限定为"转换掩码值（值域受限）"与"最终输出"两类，结构上不存在"随手解出中间激活"的路径。D5′ 延续该设计。

## 二、准备知识（正文反复使用的四样工具）

### 2.1 CKKS 同态加密（Cheon-Kim-Kim-Song, 2017）

- **是什么**：支持实数/复数向量近似同态运算的全同态加密方案——对密文直接加法与受深度限制的乘法，解密得带噪声的近似值。
- **为什么选它**：线性层是实数矩阵乘，CKKS 的 SIMD 槽打包（mode-b 一密文 16384 个实数）+ 旋转正好高效支撑。替代项：TFHE 系（布尔/整型，向量乘低效）、Paillier（仅加法）。
- **实现栈**：TenSEAL 0.3.14（捆绑 SEAL）。被迫直用 sealapi：向量旋转与显式 rescale（TenSEAL 高层无旋转 API）。
- **关键概念（后文反复用）**：
  - **槽（slots）**：一密文装的实数个数（mode-b 16384），canonical embedding 编码；
  - **scale**：定点缩放因子（mode-b 2^40），明文×scale 存为系数；乘法后 scale 相乘，需 **rescale** 归位；
  - **level / mod_switch**：乘法深度耗模数链一层；mode-b 链 [60,40,40,60]（200bit）支持 2 层乘法，转换后 fresh 重置（深度免费）；
  - **Galois 旋转 + BSGS**：密文向量循环旋转实现对角线矩阵乘；baby-step giant-step 把 O(d) 次旋转降为 O(√d)；
  - **IND-CPA**：无私钥时密文不可区分——计算方侧安全性的根据；
  - **encrypt_vector_at_scale**：按目标密文精确 scale 编码——rescale 素数非精确 2^k 导致深层密文 scale 有相对漂移，掩码必须按精确 scale 编码（P4 实测：relabeling 在 OTP 大值域误差数千）。
- **实测确认的坑**：①n≥2^16 一律 invalid_parameters（本栈上限 2^15）；②scale=1.0 编码**静默全零**；③`Modulus(40)` 是值 40 不是 40-bit 素数（用 `CoeffModulus.Create`）；④解码 **±1 ulp 抖动**：解码噪声经 `round(v·2^16)` 偶尔回差 1——全槽实测翻转率 11~26%（P8 校准，§5.9）；"环算术精确 ≠ 解码逐位精确"；⑤invariant_noise_budget 不支持 CKKS（改用解密误差 RMSE）。

### 2.2 加性秘密分享与 Beaver 三元组（Beaver, 1991）

- **是什么**：秘密 x 在环 Z_{2^64} 上拆成 m 份均匀随机数之和（Σxᵢ=x）；Beaver 三元组 (a,b,c=a·b) 离线预生成，在线公开 d=x−a、e=y−b 即完成一次乘法：zᵢ = cᵢ+e·aᵢ+d·bᵢ（+d·e 记一方）。
- **为什么选它**：非线性算子在分享域用多项式近似+Beaver 乘法，通信可控。替代项：OT/GMW（通信更大）、FHE-only（深度不可行，§1.4）。
- **实现栈**：自实现（`src/crypto/secret_sharing.py`、`beaver.py`；P8 增 `_m` 版）。D7 假设：三元组可信离线生成、生成器不合谋不在线。
- **关键概念**：**m-of-m 分享**（任意 m−1 份均匀）；**开放**（广播掩码后值，公开量不泄露）；**公开常数乘**（本地零交互，各方同乘保持一致）。
- **实测确认的坑**：①环 Z_{2^k} 非域（2 无逆元）——Shamir/拉格朗日不可直接用（P8 选加性 m-of-m 的根因）；②份额必须逐元素独立随机；③m-of-m 零容错。

### 2.3 国密套件 SM2/SM3/SM4-GCM

- **是什么**：中国国家商用密码算法族——SM2 椭圆曲线公钥（签名/密钥交换）、SM3 哈希、SM4 分组密码。
- **为什么选它**：商用合规硬约束（题面场景：政企采购要求国密）。
- **实现栈**：gmssl 库（SM2/SM3 可用；**无 GCM 模式**）→ SM4-GCM **自实现**（`src/crypto/gm_cipher.py`）+ **RFC 8998 附录 A.1** 标准向量逐字节锚定。
- **关键概念**：SM2DH（GB/T 32918.3 密钥协商，KDF=SM3）；GCM 计数器+认证标签（nonce 绝不复用：nonce=方向标签‖seq）；GMHash 表驱动实现（按字节位置线性分解，8× 提速）。
- **实测确认的坑**：①GCM 计数器偏移 bug——自洽/篡改/代数测试全过，外部标准向量一跑即暴露（升格制度：密码组合层必须锚外部标准向量）；②gmssl `sm2_generate_keypair` 返回 (pub, priv) 顺序。

### 2.4 lattice-estimator（malb）@ SageMath

- **是什么**：格密码安全强度估计器（Albrecht 等），对 LWE 参数枚举已知攻击给出最优攻击成本。
- **为什么选它**：参数安全强度不能只信库的安全表（TC128 止于 N=32768 的实测教训）。
- **实现栈**：SageMath 10.x（WSL micromamba+conda-forge），`benchmarks/security_estimator.py` 对接。**坑**：Cost 是 `collections.UserDict` 子类（isinstance 恒 False）、不可行攻击 rop=+Infinity 需过滤——提取代码 5 次事故链才稳定；WSL /tmp 跨重启易失（持久产物放 /opt）。smoke 验证 113bit（n=2048/q=2^60），存档 `benchmarks/results/estimator_logs/`。

## 三、核心功能设计（按子系统）

> 协议类内容为编号步骤；每步标注信息流视角"谁看见什么"。不变量显式写出——§五讲 bug 时回指。

### 3.1 D5′ 域转换协议族（密码学核心）

**入口（CKKS 密文 ct → m-of-m 分享）**：

1. **掩码链**（链序 P2→P3→…→Pm→P1）：每步当前计算方独立采样掩码片 rᵢ（[0,2⁴⁹) 上 2¹¹ 网格均匀，os.urandom 拒绝采样），按目标密文**精确 scale** 编码 Enc(rᵢ)，mod_switch 对齐后同态加 ct ← ct+Enc(rᵢ)。*看见*：他方只见"密文+前缀片和"，rᵢ 自己独持；
2. **白名单①解密**（P0）：链末锚点把完全掩码化密文发 P0；P0 经 `DecryptionWhitelist`（kind=masked_conversion）单钥解密 y = x+Σrᵢ（round(v·2^16) mod 2⁶⁴）。*看见*：P0 只见 OTP 域值（不知任何 rᵢ）；白名单外请求 → WhitelistError+审计拒绝；
3. **分发与份额**（P0→P1，他方本地）：y 发锚点；锚点份额 x₁ = y−r₁，他方 xᵢ = −rᵢ。

**出口（m-of-m 分享 → fresh CKKS 密文，RECRYPT）**：

4. **片准备**：各计算方持结果分享 aᵢ（Σaᵢ=v），采样出口片 sᵢ（偏置窗 [2²⁵,2³⁶)），发 (zᵢ=aᵢ+sᵢ mod 2⁶⁴, Enc(sᵢ)) 给合成方。*看见*：合成方得 OTP 值与片密文，无任何一片明文属他；
5. **密文域合成**（P2）：w = Σzᵢ = v+Σsᵢ（**m 缩放界守卫** w∈[m·lo−bound, m·hi+bound)），ct = Enc(w) − ΣEnc(sᵢ) = Enc(v)——m+1 个 fresh 密文线性组合，深度重置。

**不变量**：
- I1（环精确）：Σ份额 ≡ 真值 (mod 2⁶⁴)——破坏它=掩码剥除不干净，下游全废；
- I2（精确 scale）：叠加掩码必须按目标密文精确 scale 编码，否则 OTP 大值域下偏差数千（§5.4）；
- I3（值域守卫）：|定点值| < 2²⁴（激活域）、w 落 m 缩放窗——越界即守卫被绕过/回绕；
- I4（布局）：每个线性段输入必须是转换出口 fresh 双拷贝密文（§3.2）；
- I5（门限）：任意 size-(m−1) 合谋恰缺一片均匀掩码（t=m−1 的代数根据）。

**定量依据**：入口窗 [0,2⁴⁹)——float64 2⁵³ 精确域 ⇒ m·2⁴⁹ ≤ 2⁵³ ⇒ **m ≤ 15**（mode-b；`check_m` 强制，m=2~15 全谱实测）；出口偏置窗 lo ≥ 值域（无回绕）、hi ≤ 2³⁶（编码幅值与 53 位限制）；掩码三道精度墙与修复见上（§2.1 at_scale / §2.2）。

**已知墙**：全槽口径 y₁ 相对理想值 **±1 ulp 抖动**（解码噪声；翻转率 11~26%/槽随 m 增长，P8 实测）——环算术相对 y₁ 精确，偏差在 y₁↔理想值之间；红线 4 ulp（P4 δ≤5 记录内）；{P0,·} 合谋破防（§1.4）。

### 3.2 密文线性层（对角线打包 + BSGS）

- **机制**：权重对角线打包为明文多项式集合；密文×W = Σ 旋转(ct)·diag_k（BSGS 分解降旋转次数）；bias 用 add_plain。实现：`src/model/ops/packing.py`（layout_input/linear_cipher/build_diagonal_plaintexts）、`linear.py`（embed_and_encrypt）。
- **不变量 I4**：线性段输入必须是转换出口 fresh 双拷贝——破坏即下游读到 BSGS 垃圾槽（实测全层误差 1e13）。
- **定量依据**：768×768 单层 4.2~4.5s（CPU L=2 回环）；单密文 ≤10 块（mode-b）。
- **墙**：全系统时延主导项（12 层 ≈11min/请求推算口径）；密文维度上限 2^15。

### 3.3 MPC 非线性（minimax 多项式 + Beaver）

- **机制**：GELU 15 阶 minimax 多项式（`gelu_deg15`，P2-R1 校准）；Softmax 行内 exp（4 项/元素）+ 倒数（1+2×12=25 门）；LayerNorm 8 门/元素。门数与通信字节由 `MpcEnv` 记账（公开移位口径）。
- **口径申报（S8）**：管线 MPC 中间为 reveal-compute-reshare **模拟**（CrypTFlow/Delphi 标准仿真方法）——转换边界是真实协议，中间求值模拟+如实记账。原因：1.6MB 密文纯 Python GCM 序列化 ~20s/往返不可行；通道承载全程由玩具参数 e2e 单独验证（§5.4）。

### 3.4 控制面（认证 / 会话 / 审计 / 销毁）

- **认证**：X.509v3 结构化签名对象（S4 申报演示级）+ SM2 挑战响应双向认证；伪造/过期/异根证书拒绝（F3）。
- **会话**：SM2DH（临时公钥+epoch+transcript 签名）→ SM4-GCM 帧（39B 定宽 header：version/msg_type/session_id 16B/seq u64/timestamp/payload_len；AAD 覆盖 header+payload）；seq 每方向严格单调（先拒重放）+ 时间戳窗 ±30s + 滑动窗口（非 FIFO 预留）；**ratchet**：每 N 帧或 KEY_ROTATE 前向派生（transcript 基准=本帧之前链值）。
- **审计**：SM3 哈希链 append-only（`AuditLog._append_lock` 并发锁；200 线程并发 append 测试）；节点分文件 JSONL。
- **销毁**：密钥状态机（活跃→轮换→销毁）、bytearray 两遍覆写；销毁后收发拒绝（F6）。

### 3.5 攻击套件与判定（tests/attack/）

- 框架：`framework.py`（collect_view 内存取证/RecordingEndpoint/VerdictRecorder→attack_verdicts.json）。
- 五类攻击映射（docs/02 §2 三列表）：窃听→通道 GCM+熵分析断言；中间人→证书校验+transcript 链；结果篡改→GCM 标签+SM2 签名（CTX_RESULT）+SM3 链；重放→seq 单调+窗口+ratchet 纪元销毁；合谋→t=m−1 矩阵（§5.9）+ {P0,·} 边界演示。
- 判定：30 项 = 28 防御成功 + 2 边界演示 + 0 失败（`attack_verdicts.json::summary`）。

### 3.6 m 方门限族的实现布局（P8，全部新增文件、原文件零改动）

`conversion_m.py`（协议族核心：entry_add_piece/exit_compose_m/ComputePartyRole/check_m+m_cap）、`secret_sharing_m.py`（share_vector_n/reconstruct_n）、`beaver_m.py`（split_triple_n/beaver_multiply_n，d·e 记锚点一方）、`pipeline_m.py`（ModeBPipelineM 子类，仅覆写两个转换点）、`maskparty.py`（m 方节点）、`provision_m.py`（1+m 方供给）、`orchestrator_m.py`（编排；m=3 → 5 链路：p0-p1/p0-p2/p1-p2/p2-p3/p1-p3）。消息层零改动（复用 ConvertMaskedCtPayload/ConvertSharePayload(holder)/RecryptSharesPayload）。m=2 严格退化为主仓库行为（管线 label 一致、prob 差 ≤2e-6）。

### 5.1 P0 环境与明文基线

1. **目标**：打好"普通 CPU 服务器跑出可信数字"的地基。
2. **实现**（关键函数的作用与实现过程）：
   - **环境与模型**：Windows venv（Python 3.10.4）/CPU-only/32GB；`benchmarks/download_models.py` 先探测 huggingface.co 可达性，失败自动切 hf-mirror.com 镜像，把 BERT-base-chinese、GPT-2 124M 落到 `data/models/`；`benchmarks/finetune_bert.py` 在预训练 BERT 上接一个二分类头、用自建情感语料训练数分钟，产出 acc 99.0% 的检查点——它就是此后所有密文推理的精度参照物。
   - **性能框架 `perf_runner.py`**：全部时延数字的产地处。它按"分词→模型前向→解码"跑多轮，每轮用高精度计时器采样分段耗时，连同 torch 线程数、CPU 负载等环境快照（envinfo 字段）写进带 UTC 时间戳的 JSON。两个关键口径在这里定型：threads=8 锁定（消除 PyTorch 线程调度的轮间抖动，实测两轮能差 1.6×）；只报 P50/P95 多轮区间、不报单轮（单轮绝对时延不可作跨阶段锚点）。
   - **定点化预研 `eval_quantize.py`**：把浮点权重/激活压成整数——激活统一 Q16（16 位小数位）、GPT-2 权重 Q22、BERT 权重 INT8，并逐一验证"压缩后模型输出与浮点模型一致"（一致率 100%）。这一步决定了后面密码电路里所有数字的形态：同态电路只吃整数。
3. **出口**：评审通过。权威基线 GPT-2 P50 792.4/P95 856.5ms、BERT 38.4/49.0ms（`*_plaintext_baseline_*.json`）。

### 5.2 P1 架构与协议规格

1. **目标**：题面要求 → 可实现协议文档。
2. **实现**（docs/01 九章规格，其后所有阶段只是填实现）：
   - **三方职责与消息序列**：把系统拆成 P0（数据属主，唯一持钥）/P1（密钥服务）/P2（推理计算），并定死八类消息 S1~S8——每条消息的字段、编码（39B 定宽头+JSON 载荷）、认证方式在这一层定死。
   - **D5 转换协议的修订过程**：初版假设由计算方侧做部分解密，评审指出这会把明文路径暴露给计算方——P1-R1 修订为"解密白名单收口 P0"：P0 只允许解两类值（转换掩码值、最终输出），P1/P2 全程 public_only（构造上不持私钥）。这条修订决定了此后所有阶段的密钥分发方式。
   - **CKKS 参数表（实测定型）**：模式 B 每段只需 2 层乘法深度（同态分段+转换刷新），mode-b-segment 组（2^15 槽/[60,40,40,60] 链/200bit/scale 2^40）即可；纯同态模式 A 需要 84 层深度（2^17/链 3480bit），本栈 SEAL 对 n≥2^16 一律拒绝——不可实例化，如实写进决策记录。
3. **出口**：评审修订闭环（docs/review/P1-R1-修订对照表.md；白名单收口 P0 的设计论证见 §1.4）。

### 5.3 P3 密文推理管线

1. **目标**：模式 B 端到端贯通。
2. **实现**（`src/model/pipeline.py`，关键函数逐一说明）：
   - **密钥仪式（`__init__`）**：先建一个持钥全量上下文，把密钥文件写入临时目录后立刻销毁内存对象；随后 P0 角色从文件加载私钥、P1/P2 只加载公钥——"私钥只在 P0 角色内存中出现"从构造上保证，而非靠约定。
   - **`_convert_to_shares`（转换入口，全管线调用最频繁的函数，每层 10n 次）**：生成 16 字节 request_id → P2 角色采样全槽掩码 r 并同态叠加（ct+Enc(r)）→ P0 白名单门解密 y=x+r → y₁ 发 P1、P2 本地持 −r → 两侧份额求和还原 x。它是 I1 不变量（Σ份额≡x）的执行点——P3 的总根因 bug 就出在这里曾返回 y₁ 未减 r。
   - **`_recrypt`（转换出口）**：MPC 结果先过 to_fixed 值域守卫（|v|<2²⁴，防 OTP 回绕），重分享为两份；P1 给自己那份加出口掩码 s 并加密 Enc(s)，P2 计算 w=z+a₂ 后同态合成 Enc(w)−Enc(s)=Enc(v)——得到深度重置的 fresh 密文，下一层线性从 level 0 重新开始，不累积噪声。
   - **`_layer`（单层四段）**：段 1 QKV 三个密文线性（对角线打包+BSGS 旋转+bias）；段 2 转换后做注意力（模拟域）再 RECRYPT 后做 proj 线性；段 3 转换+残差+LN1 后 FFN1→GELU；段 4 FFN2→转换+残差+LN2。每段输入都是出口 fresh 双拷贝（I4 不变量——违反它会让 BSGS 垃圾槽混进下游，实测全层误差 1e13）。
   - **`classify`（端到端）**：文本分词→嵌入加密→逐层→CLS 密文经白名单②解密→明文池化+分类头→标签。[K] 闭环：`gen_prompts.py` 程序化生成 220 条 prompt 入库，密文/明文标签一致率 1.0000（results/ 10 份 JSON）。
3. **诚实发现**：**截断参考 n≤6 层均为随机水平（0.50）**——1 层+全 FFN 对照 0.50 佐证，是容量事实非 bug；≤3pp 判据仅 n=2 可测（0.00pp PASS），n=1 的 5pp=20 样本 1 翻转（粒度限制）；C-S"严格≤8"更正为实测 |score|=12.3。判据按事实修正，不硬凑。
4. **出口**：评审闭环（管线输出与明文截断参考一致 0.614=0.614）。

### 5.4 P4 认证与密钥全生命周期

1. **目标**：控制面全链国密。
2. **实现**（控制面五个模块，关键函数逐一说明）：
   - **认证（`auth.py`）**：CA 离线签发 X.509v3 结构化证书（`ca_issue_cert`）；握手时双方交换证书并验 CA 签名，再做 SM2 挑战-响应——挑战 nonce+应答 nonce+会话上下文一起进 SM3 摘要后签名，伪造/过期/异根证书在验证处被拒（F3 断言）。
   - **会话（`session.py` SecureChannel）**：SM2DH 临时公钥协商出会话密钥（KDF=SM3；盐用 node_id 全序规范标签 d0/d1——最初用本地收发命名，两端各自派生出了不同密钥，这是"规范标签"纪律的来历）。之后每条消息 = 39 字节定宽头（version/msg_type/session_id/seq/timestamp/payload_len）+JSON 载荷，SM4-GCM 加密（nonce=方向标签‖seq，绝不复用），seq 每方向严格单调+滑动窗口，接收侧先查重放再解密。
   - **ratchet（`keylifecycle.py` KeyManager）**：每 N 帧自动或显式 KEY_ROTATE 触发，从当前密钥单向派生新纪元并销毁旧纪元——单帧泄露不回溯污染；派生输入绑 transcript 哈希链（本帧之前的全部消息头）。
   - **审计（`audit_log.py`）**：append-only 的 SM3 哈希链，每条事件含前一条链哈希，篡改任何一条即后续全部校验失败；`_append_lock` 线程锁保证多链路并发 append 不交叉（200 线程并发测试固化）。
   - **销毁**：密钥状态机走"活跃→轮换→销毁"，bytearray 两遍覆写零化，销毁后任何收发直接抛异常（F6）。
3. **出口**：评审一次通过（2026-09-27）；`p4_protocol_bench.json`。

### 5.5 P5 威胁模型与攻击套件

1. **目标**：把"安全"变成可执行证据。
2. **实现**（docs/02 + `tests/attack/`，关键组件说明）：
   - **威胁模型文档**：敌手表 A1~A5（按"能力/前提/结果"三列）、假设核对表 A-1~A-9（密码假设/随机数/离线可信/时钟逐条锚定）、五类攻击三列表（机制→代码位置→测试）、逐算子安全分析、半诚实模拟器简化证明。
   - **取证框架（`framework.py`）**：`collect_view` 把一个节点的全部收发消息与内存态抓成快照（bytes 用 hex 标记，模式扫描须用 .hex() 口径）；`RecordingEndpoint` 伪装链路记录全部流量；`VerdictRecorder` 在会话结束把判定写进 attack_verdicts.json（summary 统计 defended/boundary/failed）——判定 JSON 按"最后一次会话落盘"，交付前必须单次全量重跑落盘。

3. **出口**：评审整改闭环（docs/review/）。

### 5.6 P6 性能与基线对比

1. **目标**：四项资源指标 + 五维对比 + 创新点 A/B。
2. **实现**（`benchmarks/run_full_bench.py`，关键机制说明）：
   - **分部累积**：按 `--parts` 选择 code_size/plaintext/cipher_matrix/traffic/node_memory/c2_selector/c3_ab/tables 逐部跑并累积进同一个 JSON；tables 部分把结果渲染成 Markdown 表并注入 docs/04/05（字节级一致是四检②的内容）。
   - **分段执行（--segmented）**：密文矩阵是内存大头——把"每配置 20 轮"拆成 5 轮一段的子进程，父进程按 `--round-offset` 逐段启动，子进程写自己的分段文件，合并时按 round 去重、统计跨段重算。这样 CKKS 池随子进程退出释放，绕开连续 20 轮的内存碎片化（20 轮单进程三连 OOM 的工程解，且先做了确定性复现证明必要性）。
   - **C2 选型器**：逐量化组合试算"端到端一致率+模型体积"，只有一致率 1.000 的组合才进体积排序——闸门判据（单层误差小的组合会把嵌入层压坏，emb_int8 一致率跌到 0.3063）。**C3 对比器**：同一密文矩阵乘任务分别跑对角线+BSGS 与 row-sum 两种实现对表（row-sum 慢 5.39×/5.14×，诚实负结果）。
3. **诚实发现**：截断层标签近并列翻转（19:1/17:3/20:0）——性能不受影响，精度满配单列，两口径禁止混用。
4. **出口**：评审三轮修订闭环。

### 5.8 收尾轮：仓库优化与发布（主仓库）

### 5.9 P8 门限可配置化（隔离沙箱 → 新仓库发布）

1. **目标**：t 从固定 1 升级为 t=m−1（部署可配置），回应题面第 5 条参数化措辞。
2. **实现**（隔离沙箱，原件零改动，全部新文件；关键函数逐一说明）：
   - **协议族核心 `conversion_m.py`**：`ComputePartyRole` 是每个计算方的角色对象——内部两个按 request_id 索引的字典（入口片表/结果分享表）；`entry_apply_piece` 采样自己的掩码片 rᵢ 并按目标精确 scale 编码叠加；`entry_own_share` 按角色位返回 y−r₁（锚点）或 −rᵢ（他方）；`exit_piece` 采样 sᵢ 返回 (aᵢ+sᵢ, Enc(sᵢ))；`exit_compose_m` 把 m 个片求和得 w、做 m 缩放界守卫后合成 Enc(w)−ΣEnc(sᵢ)；`m_cap/check_m` 把 float64 2⁵³ 精确域换算成 m 上限（mode-b 15）并在构造时强制。
   - **编排 `orchestrator_m.py`**：`links_for_m(m)` 程序化生成链路表（基础 3 条+掩码链 p2→…→pm→p1+出口星型；m=3 共 5 条）；`run_inference_round_m` 按"请求→链式加片→白名单①→份额常数乘→出口星型→合成→SM2 签名回传"顺序驱动 1+m 个节点的真实 SM4-GCM 收发；生命周期再串 ratchet/销毁/审计核验。
   - **管线 `pipeline_m.py`**：以子类方式只覆写两个转换点（单片掩码→链式 m 片；两方重分享→m-of-m），其余段原样继承——这使 m=2 与主仓库行为的退化等价可测（label 一致、prob 差 ≤2e-6）。
   - **验证面**：合谋矩阵 m=3 全 6 视角 + m=4 最坏 + 审计补测 m=5~15 每档 3 个最坏 size-(m−1) 组合 ×30 试验（`test_collusion_mparty_full.py`，本环境 11 passed 239.22s；外部审计两轮 270.68s/269.32s）——**t∈{1..14} 全域实测闭环，精确恢复率 0**；代价曲线 m=2~15（1131→8766ms、6.6→40.9 MiB/轮线性，`mparty_sweep_m2_15.json`）；m=15 边界 classify（label 与原管线一致，prob 差 1e-6）。
   - **发布**：新仓库 `lyuhan123withConfigurableParameterT`（README 模仿主仓库风格、门限主线叙事）。
3. **诚实发现**：管线级 prob 不逐位稳定（CKKS ±1 ulp 边界随机命中）——等价口径修正为 label 一致+±1e-4 窗+转换计数一致（与 [K] 口径同源）；"逐位精确"只在环算术层（给定 y₁）成立。
4. **出口**：全量 297+18+3 零失败（默认口径）；新仓库上架（README 模仿主仓库风格+门限主线；精度行按明文量化口径标注，证据指针指向 `bert_accuracy_full12_quantized`）。

## 六、关键流程时序走查（m=3 部署，一次分类请求）

1. **会话建立**（一次性）：三链路各自证书交换 → SM2 挑战响应双向认证 → SM2DH 协商（epoch 签名）→ SM4-GCM 通道+ratchet 阈值。保护层：身份绑定+机密性。出问题表现：证书伪造=AUTH 拒绝（F3）；
2. **P0 本地**：分词（8 token）→ 嵌入（明文）→ 布局打包 → CKKS 加密（level 0，~1.6MB/密文）。保护层：此后明文不出 P0；
3. **INFER_REQUEST**（P0→P2，GCM 帧）：密文载荷。敌手视角：GCM 密文（F1 窃听断言）；
4. **CKKS 线性层**（P2）：QKV/FFN 对角线矩阵乘+bias，level 0→1。破坏 I4 ⇒ 下游垃圾槽；
5. **掩码链**（P2→P3→P1）：逐跳 ConvertMaskedCtPayload，各加 Enc(rᵢ)。他方视角：前缀片和掩蔽；
6. **白名单①解密**（P0）：y=x+Σr（±1 ulp 口径）。白名单外 → 拒绝+审计；
7. **CONVERT_SHARE**（P0→P1）：y（8B/槽）。P1 份额 y−r₁，P2/P3 持 −r₂/−r₃；
8. **MPC 非线性**（计算方间）：注意力/GELU（m-of-m 分享域，门数记账）。破坏 I1 ⇒ 重构漂移；
9. **出口星型**（各计算方→P2）：(zᵢ, Enc(sᵢ)) → 合成 Enc(v)（fresh）。合成方缺任何一片无法剥离；
10. **INFER_RESULT**（P2→P0）：logits 密文+SM2 签名。验签失败拒绝（F7-3）；
11. **白名单②解密**（P0）：CLS → pooler → 分类头 → 标签。

**信息流审计小结**：P0 见明文输入/输出与掩码域值；P1 见 y 与自己的片/份额；P2 见全部密文、w、自己的片；P3 见前缀密文与自己的片；线缆全 GCM。任意 t≤m−1 计算方组合缺至少一片均匀掩码（t=m−1 门限）；{P0,·} 组合超出模型（§八.7）。

### 7.3 创新点（正负结果同等入档）

- **C2 参数自适应量化选型（正）**：端到端一致率闸门+从参考域单次量化 ⇒ conv_fp16+emb_q22 = 一致率 1.000@312.7 MiB（−34.1%）；**负结果**：逐张量 2% 阈值选择器失效、层级升级策略失效（int8 级联定型）、emb_int8 一致率 0.3063（灾难）——"按单层误差小挑组合会翻车"；
- **C3 双实现选型（正）**：对角线+BSGS 胜出；**负结果**：row-sum 慢 5.39×/5.14×，早期"快 1.3×"预估被实测推翻（解析 ρ 单位模型低估环上全宽明文编码成本）；
- **P8 门限族（正）**：t=m−1 全域实测闭环；**墙/负结果**：mode-b m≤15（float64 墙）、m-of-m 零容错、{P0,·} 超出模型、门限 CKKS 密钥两堵墙互斥（§1.4）。

## 八、诚实的边界（单独成节，与 §七成果明确区分）

1. **时延**：密文路径分钟级（回环 CPU 截断层口径），现网要求百毫秒级——GPU/定点线性层/转换批量化均未实现；
2. **模式 A 不可实例化**：SEAL 2^15 上限阻断 84 深度全密文；需 OpenFHE 级后端；
3. **满配 12 层密文端到端精度未测**：密文精度主张止于截断层一致性（`pipeline_accuracy` verdict=false 与 L=8 口径如实入档）；
4. **证书体系演示级**：结构化签名对象，非 GM X.509 链；
5. **数据面非纯国密**：控制面全链国密，密文计算引擎为国际标准 CKKS；
6. **底座模型演示级**：情感二分类微调+截断层管线，业务语义为示例；
7. **{P0, ·} 合谋破防**：P0 全钥+计算方密文 ⇒ 中间态可解——模型外如实申报；更高容忍的门限化 CKKS 密钥受两堵墙限制（§1.4）；
8. **m-of-m 零容错**：计算方掉线协议停滞；无 Shamir k<n 冗余（环上拉格朗日=域论代价）；
9. **t 供给时锁定**：会话中途不可动态增减计算方；上限 mode-b t≤14；
10. **外部效度锚点缺失**：精度为自建集同源对照（n=200）；ChnSentiCorp 等公开集三口径未做（登记 [L]，"已登记未完成"口径应答）；
11. **GPT-2 密文生成未实现**（task_gpt2_cipher 如实申报 N/A）；
12. **MPC 中间为模拟口径**：转换边界真实协议+玩具参数通道 e2e 验证，管线内 MPC 求值为 reveal-compute-reshare 模拟（S8 申报）。

## 九、常见问题（技术向 FAQ）

1. **密文推理为什么分钟级？** 瓶颈=CKKS 明文矩阵乘（768×768 单层 4.2~4.5s，§3.2）+ 每层 10n 次域转换往返（§3.1）。文献 MPC 同为数量级开销（§7.2）。
2. **t 为什么上限 14？为什么不是真 Shamir？** mode-b 掩码总窗 ≤ m·2⁴⁹ 必须落 float64 2⁵³ 精确域 ⇒ m≤15（§3.1）；Shamir 需要域而分享域是环 Z_{2^64}（2 无逆元），拉格朗日不可用——扩域/双分享是域论代价（§2.2/§1.4）。
3. **P0+P2 合谋为什么破防还能叫"抵抗合谋"？** 声明口径是"计算参与方 t=m−1"（P0=数据属主信任根，客户端辅助 MPC 标准模型），且 {P0,·} 破防事实留表申报不隐藏（§1.4/§八.7）。纳入 P0 需门限化 CKKS 密钥——s² 交叉项与泛洪-精确回收两堵墙互斥（§1.4）。
4. **99.00% 是密文推理精度吗？** 不是——它是 INT8+Q16 明文量化满配精度（`plaintext.bert_accuracy_full12_quantized`，§7.1）。密文侧主张是"截断管线标签与明文同构参考一致"。这是全文最易误读的口径，docs/04 §6 明令两口径禁止混用。
5. **数字可信怎么自证？** 四检（§四）：字典 93 条逐字段回读源 JSON、注入表字节一致、过期值黑名单零命中（黑名单成员就是历史上真实出现过的错误数字）、互引完整。
6. **模式 A 为什么不可实例化？** 全密文需 84 层乘法深度（2^17/3480bit），SEAL 对 n≥2^16 校验拒绝（§1.4/§2.1）；需 OpenFHE 级后端。
7. **攻击判定里 2 项"边界演示"是什么？** 模式 B 满额合谋（t=m−1）恢复 token 的自动化演示——预先申报的构造边界，不是漏报的攻击成功；模式 A 同场景防御成功（§5.5/§7.1）。

### A.1 定位与评审视角

### A.3 逐章写作细则

**第 1 章 方案概述（~1.5 页）**

- 小节结构：1.1 业务痛点（政务/企业两场景各一段）→ 1.2 一句话方案 + 总体架构图（图 1）→ 1.3 结果亮点表（5~6 行）。
- 素材：痛点=docs/00 §1 原文压缩（法规只引《个人信息保护法》一句）；架构图=README 顶部 mermaid 或 `docs/实现流程图.svg` 裁剪；亮点表=解释书 §7.1 摘行（密文管线一致性 / 合谋 t∈{1..14} 全域闭环 / C2 −34.1% / 攻击 28+2+0 / 代价曲线线性 / 四检闭环）。
- 写法要点：本章不出现实现细节；每个亮点 = 一句主张 + 一个口径限定词。
- 示例句式（合谋亮点）："部署 m 个计算方即可抵抗至多 t=m−1 方合谋——t∈{1..14} 全域实测闭环，最坏组合 30 试验精确恢复率 0。"
- 常见错误：把 99.00% 写成"密文推理精度"（必须"INT8+Q16 明文量化满配精度"）；架构图里出现 P0~P8 阶段编号与角色编号混淆。

**第 2 章 威胁模型（~1.5 页）**

- 小节结构：2.1 敌手与信任假设 → 2.2 敌手能力表（A1~A5 摘录）→ 2.3 安全假设（A-1~A-9 按类归组：密码假设/随机数/离线可信/时钟）→ 2.4 合谋模型与门限声明。
- 素材：docs/02 §1.2/§1.3/§6 + 附录 A；解释书 §一。
- 必写内容：**半诚实参与方+恶意网络**口径；**P0=数据属主信任根**（客户端辅助 MPC 标准模型）与 {P0,·} 超出模型的申报；t=m−1 声明与"供给阶段锁定"。
- 写法要点：假设逐条编号（正文引用 A-x）；每个假设后括注"它保护什么/被打破会怎样"。
- 常见错误：把"半诚实"写成"恶意安全"；漏 {P0,·} 申报（评审一问即穿）。

**第 3 章 协议设计（~4 页，技术主体之一）**

- 小节结构：3.1 系统架构与消息序列（图 2 时序图）→ 3.2 D5′ 域转换协议族 → 3.3 密文线性层 → 3.4 MPC 非线性 → 3.5 控制面国密 → 3.6 参数与安全强度。
- 3.2 写法（报告书语气改写解释书 §3.1）：入口三步/出口两步编号步骤，每步括注"谁看见什么"；随后给**不变量清单 I1~I5**；安全语义一段（缺片 OTP：任意 t≤m−1 方合谋缺一片均匀掩码，信息论隐藏，泄漏界不随 m 劣化）；m 上限一句（float64 2⁵³ 域 ⇒ mode-b m≤15）。
- 3.3/3.4 写法：机制两句 + 定量依据一句（4.2~4.5s/层；deg15；门数记账）+ **S8 模拟口径申报**（MPC 中间为 reveal-compute-reshare 模拟、转换边界真实协议——必须写，评审会问）。
- 3.5 写法：六组件表（认证/SM2DH/SM4-GCM/ratchet/审计/销毁），每行末"安全性根据"（如 RFC 8998 外部向量锚定、200 线程并发审计测试）。
- 公式直接给：份额和 Σxᵢ=x、Beaver zᵢ 定义、合成 ct=Enc(w)−ΣEnc(sᵢ)。
- 常见错误：协议步骤丢"谁看见什么"；把模拟口径写成真实 MPC；忘写 m 上限的推导只给结论。

**第 4 章 实现与正确性保障（~2 页）**
