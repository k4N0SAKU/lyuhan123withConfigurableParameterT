## 二、加解密速度优化

### 2.1 已实施：2^16 评审路径 PoC（N=2^16 单点加解密实测）

- **机制**：给 `CKKSContext` 增加 `sec_level`（TC128/NONE）与 `galois`（跳过 Galois 全集）构造参数；新增参数组 `mode-b-2e16-REVIEW-PATH`（N=2^16/链 [60,40,40,60]/32768 槽）。SEAL 的 TC128 校验表止于 N=32768，2^16 需 NONE 口径——安全性改由 lattice-estimator 承载（C≈2^130.2≥128，docs/01 §5.3 登记值）。
- **实测**（`poc_2e16.json`，32768 槽随机向量）：

| 项 | 数值 |
|---|---|
| keygen（无 Galois 集合） | **977ms**（全集 ≈45min——Galois 最小集为另一独立工作） |
| 密文尺寸 | 2.51 MiB（理论 3.28MB 差异为 size_bytes 口径待复核项，如实注记） |
| **加密**（16384 值全槽） | **36.1ms** |
| **同态加**（转换入口原语） | **1.7ms** |
| **解密** | **8.4ms** |
| 双倍往返精确性 | max_dev=1（±ulp 口径，翻转率 0.11%，红线 4 内） |

- **效果与意义**：2^16 路径的单点加解密**可用且快**（N 翻倍后加密仅 36ms），转换次数减半（240→120/请求）——路径已实证，主线切换待团队评审（安全口径 TC128→NONE+estimator）。
- **±ulp 发现**（本轮校准，适用于全部参数组）：解码噪声经 `round(v·2^16)` 存在 ±1 抖动（全槽实测翻转率 0.1~26% 随配置）——"环算术精确（给定 y₁）"与"解码逐位精确"是两个口径；全部基准已统一 ±4 ulp 红线。

### 2.2 评估后不实施（如实记录）

- **BSGS baby/giant 调参**：现启发式（baby=⌈√d⌉ 取整除）对 d=768 给出 32×24 分裂，旋转 54 次 vs 理论最优 53.6——**余量 <1%**，无调参价值；布局级收益在 EncFormer folded-diagonal/旋转银行（依赖 GPU 化）。
- **GPU 化线性层**：预期 10~50×（371.8s→10~30s 量级）——**本机 CPU-only 无硬件**，登记为待硬件项（方案：线性段迁 PhantomFHE 级 GPU 库，转换段留 CPU）。

### 2.3 历史既有优化（P2 轮已入档，此处索引）

- BSGS 旋转公式（旋转次数 (baby−1)+(giant−1)，明文乘同 level 累加统一 rescale——净耗深度 1）；
- SM4-GCM 的 GHASH 表驱动实现（按字节位置线性分解，**8× 提速**）；
- 全部沿用至今，数字见 docs/phases/P2-工作记录.md。

## 三、通信开销优化

### 3.1 基线

每转换往返通信（二进制口径）：m=2/3/4/5 = **6.65/9.29/11.91/14.55 MiB**；每请求推算 2.81 GiB（m=3、L=16）；另有**线上 2× hex 膨胀**（数据面载荷以 hex 文本嵌 JSON 传输，P9 过程中发现——见 3.2.2）。

### 3.2 已实施

#### 3.2.1 出口掩码离线预生成库存（3a）

- **机制**：D7 延伸——可信离线生成器预采样 sᵢ 并加密 Enc(sᵢ) 入库；在线各方只发 zᵢ=aᵢ+sᵢ（8B/槽），合成方从库存取 Enc(sᵢ)。门限语义不变（sᵢ 仍各方独持、一次性使用、size-(m−1) 合谋恰缺一片）。
- **过程要点**：首版整库单文件+全库 SM3（gmssl 纯 Python 0.25MB/s）实测卡死——重构为**清单+分条目文件**（fetch 只触本条目），SM3 改用 OpenSSL C 实现（**388MB/s，为 gmssl 参考实现的 1500×**，摘要与 SM3 标准测试向量交叉验证一致）。
- **实测**（mode-b 全槽、3 轮/档，`mparty_cost_curve_store.json`）：

| m | 出口通信（基线→库存） | 削减 | 每轮总通信（基线→库存） | 削减 | 出口时延（基线→库存） |
|---|---|---|---|---|---|
| 2 | 4.02→1.51 MiB | **−63%** | 6.65→4.14 MiB | −38% | 488→295ms |
| 3 | 5.39→1.63 MiB | **−70%** | 9.29→5.52 MiB | −41% | 744→352ms |
| 4 | 6.77→1.75 MiB | **−74%** | 11.91→6.90 MiB | −42% | 942→479ms |
| 5 | 8.15→1.88 MiB | **−77%** | 14.55→8.28 MiB | −43% | 1163→593ms |

（离线预生成 1.5~3.5s/档·3 轮单独计时，不计入在线；库存一次性使用、耗尽即协议中止。）

#### 3.2.2 数据面二进制帧（协议 v2）

- **机制**：数据面五载荷的大字段（bytes）从 JSON hex（2× 膨胀）迁至信封级 blob（原始二进制、4B 长度前缀）；小 JSON 内以 SM3+长度绑定；`header.version=2` 门控 v1/v2 双解码（控制面与 v1 路径零改动）；SM2 签名覆盖段=重建后完整载荷的 JSON（两侧字节一致，签名机制零改动）。
- **实测**：ConvertMaskedCtPayload（1MiB 密文载荷）线上 **2.00→1.00 MiB（−50.0%）**；blob 单字节篡改即 SM3 拦截；签名覆盖段 v2 往返前后一致（`test_messages_v2.py`）。
- **集成验证**：m=3 生命周期 e2e（真实 SM4-GCM 通道全程 v2 帧）通过；全量 265+2+3 零失败。

### 3.3 成本模型与叠加路径（`benchmarks/cost_model.py`，先验）

| 场景（m=3、L=16） | 每请求转换通信 |
|---|---|
| 2^15 现状 | 2.81 GiB |
| + 出口库存（已实施） | 1.65 GiB |
| + 模数裁剪（EncFormer 实测 0.3× 先验） | 1.04 GiB |
| + 复数打包（0.5× 先验） | **0.58 GiB（4.8×）** |
| 2^16 + 全部杠杆 | 0.41 GiB |

（裁剪/复数为 EncFormer 实测先验系数，落地须重测；模型暴露的转换计数三口径疑点已登记 P9 提案 §2.3。）

### 3.4 登记未实施

模数裁剪（需重推 64 位环安全条件）、复数打包（布局改造）、2^16 主线切换（团队评审）、分享环 2⁴³（向量项 −25%，小头）。
