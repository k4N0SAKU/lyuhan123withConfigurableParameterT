## 0. 工时口径声明（D8：不编造）

本项目为 AI 流水线执行 + 团队阶段评审的协作模式，**不存在人时打卡系统**。
本报告"实际工时"采用**代理口径**：①阶段首末提交的 git 时间跨度（可复核：
`git log --format="%h|%ad|%s" --date=format:"%m-%d %H:%M"`）；②评审发生在
阶段交付之后（评审日期见各阶段记录）。P0~P2 的原始提交链在 2026-09-26
搬迁事故中丢失（重建 551554c），该三段以工作记录日期为代理。**跨度包含
长任务挂机时间**（基准矩阵 ~4h、estimator 数小时、模型下载等），不等于
净开发时长——请按此口径解读。

## 2. 计划偏差归因（诚实清单）

1. **搬迁事故（09-26）**：C 盘源丢失 → 重建 + 三份工作记录/对照表有损
   恢复 → P3-R1 追加"事故重建完整性"整改（E 项）。净影响 ~半天；
2. **评审返工轮次**：P1-R1、P2-R1、P3-R1、P5-R1、P6-R1/R2/R3 共 7 轮
   修订——计划内质量门，但 P6 三轮 + est­imator 六次事故链显著超出预期；
3. **环境受阻（超计划）**：lattice-estimator 六路受阻（pip/四 Docker 镜像/
   WSL apt）后 WSL micromamba+conda-forge 路线打通，跨 P3~P6 多次返工；
   最终以"原生日志存档+解析恢复+smoke 端到端验证"闭环；
4. **矩阵 OOM（超计划）**：单进程形态在本机 32GB 必然失败（重试实证）→
   逐层子进程+分段合并契约 → 三次跑数尝试才拿到 20/20×3；
5. **范围级终裁（决策项非偏差）**：模式 A 不实例化（栈上限）、2^15 提交/
   2^16 报告书路径、[L] 外部锚点移交 P7、[I] 随 socket 化——全部登记在案。

## 4. 三阶段教训索引（跨项目可复用）

1. **修复必须带"原数据还在不在"对账**（estimator smoke 覆盖决策 JSON——
   第 6 次事故后确立）；
2. **替换式修改必须验证旧值已替换且传播到全部引用点**（R2 文档半边虚报、
   heredoc 续行符静默失配两次）；
3. **后台产出立即归档入仓，不留 /tmp**（WSL 跨 VM 清理吞过日志与仓库）；
4. **长跑必须独占内存**（并发挤压放大 SEAL 池峰值 → OOM 三连）；
5. **密码组合层必须外部标准向量锚定**（GCM 计数器偏移只有 RFC 8998 抓到）。
