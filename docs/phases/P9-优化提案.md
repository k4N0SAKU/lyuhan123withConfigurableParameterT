## 2. 已执行（快赢批+文献批）

### 2.1 3a 出口掩码离线预生成库存（在线通信最大单项优化）

- **机制**：D7 延伸——可信离线生成器预采样 sᵢ 并加密 Enc(sᵢ) 入库；在线各方只发 zᵢ=aᵢ+sᵢ（8B/槽），合成方从库存取 Enc(sᵢ)。门限语义不变（sᵢ 仍各方独持、一次性使用；size-(m−1) 合谋仍恰缺一片）。
- **架构教训（固化为设计）**：条目含 MB 级密文 hex ⇒ 整库单文件+全库 SM3（gmssl 纯 Python 0.25MB/s）实测卡死 30+ 分钟 ⇒ 重构为**清单+分条目文件**（fetch 只触本条目）+ SM3 用 OpenSSL C 实现（hashlib，388MB/s=gmssl 1500×，与 gmssl 参考实现交叉验证一致）。
- **实测**（mode-b 全槽，m=2~5×3 轮，`mparty_cost_curve_store.json`）：

| 2 | 4.02→1.51 MiB | −63% | 6.65→4.14 MiB | −38% | 672→489ms |
| 3 | 5.39→1.63 MiB | −70% | 9.29→5.52 MiB | −41% | 994→612ms |

（离线预生成成本单独计时：1.5~3.5s/m·3 轮，不计入在线；库存一次性使用、耗尽即中止。）

### 2.2 1b 2^16 评审路径 PoC（不切主线）

- `ckks_ops.py` 增加 `sec_level`（TC128/NONE）与 `galois`（跳过 45min 全集 keygen）构造参数 + `PARAMS_MODE_B_2E16` 参数组；
- 实测（`poc_2e16.json`）：SEAL 接受 N=2^16（NONE）；slots=32768；ct 2.51MiB；keygen（无 Galois）977ms；加解密 roundtrip max_dev=1（±ulp 口径，翻转率 0.11%）；转换次数减半（120 vs 240/请求，本模型口径）。
- 安全 provenance：estimator C≈2^130.2≥128（docs/01 §5.3 登记值）；诚实注记：实测 ct 2.51MiB < 理论 3.28MB——size_bytes 口径待复核（不影响结论）。

### 2.3 2c 成本分析模型（`benchmarks/cost_model.py`）

- 先验模型（常数全部实测来源标注）：m=3 场景矩阵——现状 2.81 GiB/请求 → 库存 1.65 → 库存+模数裁剪（EncFormer 0.6×先验）1.04 → +复数打包（0.5×先验）**0.58 GiB（4.8×）**；2^16 路径同系数再减 25%。
- **口径疑点（登记）**：docs/01 §5.3「转换 192 次」vs「10n/层」公式 vs 实测 conversions=10 点/层——三种口径在 L=16 下不一致（本模型采用实测口径 240/120），待对照管线实测核实。

### 2.7 1 号方案落地：数据面二进制帧（协议 v2）——线上通信再 −50%

- **机制**：数据面五载荷（INFER_REQUEST/INFER_RESULT/CONVERT_MASKED_CT/CONVERT_SHARE/RECRYPT_SHARES）的大字段（bytes）从 JSON hex（2× 膨胀）迁至信封级 blob（原始二进制、4B 长度前缀拼接）；小 JSON 内以 SM3+长度绑定；`header.version=2` 门控 v1/v2 双解码（控制面与 v1 路径零改动）；SM2 签名覆盖段=重建后完整载荷的 JSON（签发/验证两侧字节一致，签名机制零改动）。
- **实测**：ConvertMaskedCtPayload（1MiB 密文载荷）线上 2.00→1.00 MiB（**−50.0%**，test_messages_v2 断言 0.4<saving<0.6）；blob 单字节篡改即 SM3 拦截；签名覆盖段 v2 往返前后一致。
- **集成验证**：m=3 生命周期 e2e（真实 SM4-GCM 通道跑 v2 帧）全绿；全量 265+2+3 零失败。
- **叠加效应**：与 3a 库存、模数裁剪、复数打包全部正交——成本模型口径的每请求线上通信（含 hex 税）5.6 GiB → 二进制帧后 2.8 → 全杠杆叠加 ~0.6 GiB（≈10×）。
