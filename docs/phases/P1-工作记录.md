## 2. 关键设计决策与推导（评审重点材料）

### 2.1 模式 B"分段刷新上下文"定理（§5.1）
每次密文→分享→密文转换后返回 fresh 顶层密文 ⇒ 密文深度重置 ⇒ 模式 B 密文
只需段内深度 2。推论链：
- 模数链 [60,40,40,60]=200bit（远低于 2^16 的 1740bit 安全上限）→ 密文
  3.3MB（若用全深链则 28.2MB，缩小 8.5 倍）→ 转换通信同比例下降；
- **深度消耗与层数无关**：残差主干经 mod-switch 稳定 pin 在链底 level
  （深度 2），任何时刻链深恒为 2——BERT 与 GPT-2 全模型用同一套深度 2
  分段链跑通，不存在按层数的累计深度（P1-R1 修订 C 项统一口径）；
- 模式 A 无刷新 → 每层 42 深（exp 按 PS 深度 4 计，R1 修正）→ 12 层 504 深
  **定量判定不可行**；2^17（84 深）承载 2 层截断（84=84 满载、余量 0，P2
  噪声实测后可下调至 1 层）→ 模式 A 演示配置 n_layer=2 为上限目标。

### 2.2 残差处理
BERT post-LN：残差 h=x+Attn(LN(x)) 在 add 前 mod_switch 对齐低 level；
GPT-2 pre-LN：残差主链每层走 2+2 深，add 前对齐——均不加深度。

### 2.3 通信量诚实估算（§6.3/§7.5）
模式 B 无优化基线：转换 96 次 × 13.3MB ≈ 1.28GB + MPC 0.9GB ≈ **GB 级/请求**
（L=16）；显著高于文献最优（BumbleBee MB 级），差距来源与优化路径
（大槽位 2^17/链裁剪/转换合并）如实列出，供 P6 实测对比。

### 2.4 模型对 P0 公开的信任边界
嵌入查表留在 P0 本地（P0 已知 token，查表不增加其信息量——信息论论证）；
保护目标是用户输入与中间激活（题面要求 1/5），不含模型保密；docs/02 §2.2
声明，模型保密需求列为扩展项（OVS 查表）。

1. **CKKS 槽数规格错误**：初版误把 2^16 poly 当 65536 槽——CKKS 槽数 = N/2
   = 32768 → 打包布局修正（每密文 21 个 1536-槽 token 块），代码/测试/文档同步。
2. **接口测试调用方式**：无参调用带参方法触发 TypeError 而非
   NotImplementedError → 按 signature 补齐占位实参。
3. **docs/02 章节编号错乱**（前向安全论证 3.2/3.3 重复）→ 修正为 3.4 并同步
   docs/01 交叉引用。
4. **模式 B 参数链初版过深**：初稿按"全模型累计深度"设 40 层链，推演转换
   刷新机制后修正为深度 2 分段链——骨架测试（参数锚定）随规格同步修订。
