## 1. 协议层实现（任务 1~4）

### 1.1 messages.py——信封序列化（S7）
- `serialize_envelope`/`deserialize_envelope`：定宽头 39B（version u8‖type
  u16‖session_id 16B‖seq u64‖ts u64‖payload_len u32）+ 规范 JSON 载荷
  （sort_keys+紧凑分隔符；bytes 以 `{"__hex__":…}` 标记包保真往返）；
- `canonical_bytes` = 签名/哈希覆盖段（不含 auth_value）；
- 19 类载荷与 CommonHeader 维持 P1 定义；`RecryptSharesPayload` 修订为
  `{enc_mask, masked_share_ints}`（见 §3.2，docs/01 §7.4 修订记录同步）。

### 1.2 auth.py——证书与双向认证（F3）
- 结构化签名证书：`ca_issue_cert`/`verify_cert`（CTX_CA 独立上下文；
  65B 未压缩公钥格式校验；有效期窗口含 60s 时钟偏移容差）；
- CA 根离线：`src/nodes/provision.py` 生成根密钥+三节点证书+CKKS 密钥材料
  （公钥材料给 P1/P2、私钥仅 P0——D5 分发口径），根私钥不进任何在线节点；
- 挑战-应答：`issue_challenge`（os.urandom 32B，单次使用，TTL 30s 可配置）/
  `respond`/`verify_response`/`make_result`/`verify_result`；
  digest = SM3(域分隔前缀‖发起方 id‖应答方 id‖challenge‖responder_nonce)；
- 拒绝矩阵（测试对齐 docs/01 §3.4 错误码）：伪造/篡改证书 CERT_INVALID、
  过期 CERT_EXPIRED、nonce 不回填/挑战复用/签名人不符 AUTH_FAILURE；
  反射防护：digest 绑定角色序（发起方在前）+ 每类签名独立上下文字符串
  （test_reflection_blocked 断言跨上下文签名验证失败）。

### 1.3 session.py——SM2DH 与安全通道
- **SM2DH（GB/T 32918.3 核心）**：自实现点加法（gmssl 底层仅有标量乘）+
  w 截断（x̄=2^w+(x mod 2^w)，w=128）+ V=t·(P_peer+x̄_peer·R_own)；
  临时公钥经静态私钥签名（覆盖 eph_pub‖epoch‖session_id，CTX_KEY）——
  MitM 替换临时钥/静态钥均被确认标签检出（test_sm2dh 双用例）；
  KDF(x_V‖y_V‖Z_init‖Z_resp, 32)（Z 按 GB/T 32918.2）；
  **确认标签替代声明**：国标 Option S1/S_B 确认哈希以 SM3(shared‖salt)
  截断标签替代——确认消息本就在已认证信封内，安全目标（密钥一致性+双方
  持有证明）等价；完整 S1/S_B 列为扩展方向（docs/01 §8）。
- **SecureChannel**：帧格式 `u32 len‖u8 mode‖header‖…`（mode=1 GCM：AAD=
  mode‖header，nonce=方向标签 SM3(sid‖sender)[:4]‖seq——nonce 与 (seq,对端)
  绑定校验；mode=2 握手明文+SM2 签名）；seq 每方向严格单调（先于解密的
  重放检查）+时间戳容差窗（默认 30s，注入时钟测试）；
  F9：整帧字节（含协议头）经 NetworkMeter 统一计数；
  关键控制消息（KEY_ROTATE/KEY_DESTROY/INFER_RESULT）GCM 之上另附 SM2
  签名（payload 覆盖段，CTX_KEY/CTX_RESULT）。
- **握手时序**：CERT_A→CERT_B→HELLO×2→CHALLENGE→RESPONSE→RESULT→
  KEY_NEGOTIATE×2→KEY_ACK（应答方收证书后立即回证书——初版顺序死锁，
  P4 单测暴露并修复）；transcript 链 H_i=SM3(H_{i-1}‖header) 收发双侧
  等价更新（初版漏收侧更新致两端 root 不一致——单测暴露并修复）。
- **ratchet**：发送侧触发（messages=64 / bytes 二选一可配置）→ 先发
  KEY_ROTATE（旧钥承载）再切换；接收侧验签+transcript 基准校验（本帧
  **之前**的链值，FIFO 严格对应）后前向派生；上一纪元密钥共存窗口
  ACCEPT_WINDOW=8（语义见 keylifecycle docstring——FIFO 下重放由 seq 先拒，
  窗口为非 FIFO 预留）。

### 1.4 keylifecycle.py——状态机与登记表（F5/F6）
- KeyLifecycleState 五态；非法转换抛 KeyLifecycleError(STATE_ILLEGAL)；
- **密钥登记表（陷阱 2）**：派生树全部节点在册——sm2dh_shared（KDF 中间值）、
  root_key、每方向每纪元通道密钥；destroy 逐条「随机+0 两遍覆写」+全零

- Python 语义申报：密钥 bytearray 驻留、调用密码原语边界即时 bytes 转换
  （短生命周期拷贝不可回收——S3 纪律声明，docstring+测试注释双处声明）。

### 1.5 audit_log.py——SM3 哈希链（F5）

  定位化错误（seq 断裂=删除、prev_hash 不接=链断、hash 重算不符=篡改、
  时间戳回退=重排佐证）；JSONL 导出/加载往返；注入时钟（陷阱 1）。

## 2. D5 转换真实路径（评审指定 P4 落地项）

### 2.1 协议实现（conversion.py）
- **入口（D5 白名单①执行点）**：P2 采样 r → `encrypt_vector_at_scale`
  （按目标密文精确 float scale）→ mod_switch 对齐 → ct′=ct+Enc(r)（密文域）
  → P0 `DecryptionWhitelist.decrypt("masked_conversion", …)` → y₁ 分发 P1；
  P2 持 −r；重构 (y₁−r) mod 2⁶⁴ = x·2¹⁶（环算术精确，CKKS 噪声 ≤ 数 ulp）。
- **出口**：P1 采样 s → z=(a₁+s) mod 2⁶⁴（OTP）+ Enc(s) → P2 计算
  w=(z+a₂) mod 2⁶⁴=v+s → ct=Enc(w)−Enc(s)=Enc(v) fresh 顶层（深度重置）；
  P2 从不获 s 明文、P1 从不获 a₂（docs/01 §7.4 t=1）。
- **DecryptionWhitelist**：P0 私钥唯一访问门（结构性：`_secret_ctx` 私有，
  节点上无绕行路径）；两类放行 + 拒绝事件审计；P1/P2 结构性 public_only。
- **偏置 OTP 掩码（CrypTFlow 式溢出控制）**——P4 两次实测迭代的结论：
  | 发现 | 量级 | 处置 |
  |---|---|---|
  | 全宽 2⁶⁴ 掩码 + level≥1 密文：rescale 素数非精确 2^k → scale 相对漂移 ~1.4e-6，relabeling 加法在 OTP 大值域引入 | ±2¹² 分享偏差（mode-b 规模测试暴露） | 掩码密文按目标密文精确 scale 编码（encrypt_vector_at_scale） |
  | float64 精确整数域 2⁵³：P0 侧 round(y·2¹⁶) 超域 | y₁ 偏差 ±2¹¹ | 入口窗收缩 |
  | 掩码值量级 ↑ ⇒ 解密重构 ulp 抖动与编码残差线性放大（2³⁷→δ≤5/2.4e-6） | 出口合成精度 | 掩码值统一 ≤2²⁰ |
  最终 mode-b 策略（ConversionPolicy，规格 docs/01 §7.4 同步）：值域守卫
  2²⁴（激活域 ±256）、入口窗 [0,2⁴⁹)（2¹¹ 网格）、出口窗 [2²⁵,2³⁶)；
  边界统计泄漏 ≤2·2²⁴/2³⁶ = 2⁻¹¹ bit/slot（实测激活 |v|≤2⁸ 时 ≤2⁻¹⁹）。

### 2.2 管线接线（pipeline.py）
- 密钥分发：构造时一次密钥生成 → 私钥仅驻留 ClientRole，计算侧 public_only
  （`OpNotAllowedError` 结构防线——管线代码路径解密已不存在）；
- `_convert_to_shares`/`_recrypt` 改为角色直连真实路径（S8 模拟口径：进程内
  直连，通道承载全程由 nodes e2e 玩具参数验证——1.6MB 密文纯 Python GCM
  序列化开销不可行，诚实申报）；MPC 中间仍为 reveal-compute-reshare（P3
  S8 口径不变）；
- `classify` 末段新增：LN2 出口 → 出口重加密 → P0 白名单②最终解密
  （D5 执行点完整化；转换数公式 9n+(n−1) → **10n**，锚点测试同步）。

## 3. 节点编排（任务 5）

- **链路**：LoopbackLink（进程内 queue 对）/MpLink（mp.Queue 对）全双工、
  每方向 FIFO；初版 create_pair 两端未连通的单向队列缺陷由首个握手测试
  暴露并修复；
- **节点**：ClientNode（持钥+白名单门）/KeyNode（入口分享保管+出口准备）/
  InferNode（入口掩码+出口合成+S8 常数乘演示）——均 public_only 除 P0 外；
- **编排**（orchestrator.py）：establish_all（每链路双线程握手）→
  run_inference_round（INFER_REQUEST→CONVERT_MASKED_CT→CONVERT_SHARE→
  RECRYPT_SHARES→INFER_RESULT(SM2 签名验签)→白名单②解密，真实通道+真实
  转换协议、MPC 中间 S8 常数乘 2·x 往返）→ force_ratchet → destroy_all →
  审计核验+轨迹采集；
- **多进程模式**：三真进程（Windows spawn 安全：模块级 worker、身份文件
  供给、无 CKKS 冒烟）——认证/会话/GCM 往返/销毁全流程；握手接收超时
  参数化（180s，spawn 启动耗时）；ping 按本端全部链路成对（初版单链路
  配对错误由实测暴露）；
- **日志按节点分文件**：logs/p0_client.jsonl / p1_keynode.jsonl /
  p2_infernode.jsonl。
