## 1. 这是什么项目

**一句话**：用户输入在本地加密后，大模型推理全程只见密文/秘密分享——
政务/企业两类敏感文本场景下，情感研判结果经"白名单掩码解密"返回客户端，
推理节点自始至终拿不到明文；全栈国密（SM2/SM3/SM4-GCM）管住身份、
完整性与密钥生命周期。

| 维度 | 内容 |
|---|---|
| 赛事 | 第十一届全国密码技术竞赛复赛 A1-22 题 |
| 模型 | BERT-base-chinese 情感二分类（演示主线）+ GPT-2 124M（生成口径） |
| 密码栈 | CKKS（TenSEAL/SEAL）+ 模 2^k 加法秘密分享 + Beaver 三元组 + SM2/SM3/SM4-GCM |
| 形态 | 三方节点（P0 客户端 / P1 密钥节点 / P2 推理节点）+ 离线 CA + FastAPI 演示系统 |
| 规模 | 代码 9,949 行；测试 243 passed + 16 deselected + 3 xfailed；文档七份终稿 + 数据字典 93 条 |
| 证据 | 一键复现 6 步（reproduce_logs/）+ 攻击自动化 30 项判定 + 10 轮演示稳定性 |

**业务痛点（00 §1）**：政务 12345/一网通办评价、企业客服质检——文本
含个人信息，直接送第三方大模型推理即泄露；三共性约束：明文不出本地、
推理方零明文、结果只回业务结论。两类场景在演示系统里做成双场景切换
（src/demo/scenarios.py，政务"诉求情绪研判"/企业"客服质检"）。

## 2. 系统怎么工作

### 2.1 拓扑与一轮推理的生命周期

```
离线CA(provision.py)：SM2证书×3 + CKKS公钥分发
P0客户端 ─SM2双向认证→ P1密钥节点 ─SM2→ P2推理节点
  ①P0本地加密输入 → ②channel密文流转 → ③CKKS密文线性层(对角线+BSGS)
  ④非线性=minimax多项式+MPC求值 → ⑤Beaver三元组在线乘法
  ⑥白名单掩码解密(只出"正面/负面+概率") → ⑦审计链核验+密钥销毁覆写
```

演示状态机（src/demo/runner.py）：PROVISION → AUTHENTICATING →
SESSION_READY → INFERRING↔DECRYPTING（逐轮）→ DESTROYING → DONE。

### 2.2 模式 A / 模式 B（如实申报的双路线）

- **模式 B（主线，可运行）**：CKKS 密文域 + 模 2^k 分享域的混合——
  密文↔分享转换走真实路径（src/protocol/conversion.py，D5 白名单执行点）；
- **模式 A（如实申报不可实例化）**：纯分享 MPC 路线在本栈**不冒充可运行**——
  演示 UI 有明确的 MODE_A_UNAVAILABLE 状态。这是诚实申报口径，
  攻击测试 F8 对两种模式分别执行，模式 B 的 t=2 合谋是**预先声明的
  构造边界**（docs/02），不是失败。

### 2.3 三条"明文不出本地"防线

1. **入口**：敏感字段（姓名/证件号）P0 本地合成，随文本在加密前合入；
2. **运行时**：每轮扫描 P1/P2 全字段视图断言明文字节 0 命中（F8 同技法）；
3. **出口**：D5 白名单解密——只有情感标签/概率能解出，其余掩码销毁。

## 4. 关键决策（有据可查的编号决策）

- **D2/S3 国密纪律**：gmssl 原语 + 标准参数，自研一律封装不重造；
- **D4 模型选择**：GPT-2 124M（生成）+ BERT-base-chinese（分类），CPU 可推理；
- **D5 白名单解密**：出口只解业务结论；配套修订——threshold.py 降级为
  协议逻辑级模拟层并如实标注"主线不用"（docs/01 §8.4）；
- **D7 离线假设**：Beaver 三元组离线预生成（docs/02 §1.3 假设核对表）；
- **D8 性能数据纪律**：性能结论只允许由 benchmark 脚本写入 results/、
  文档数字必须与 JSON 一致、报告强制绝对路径归一化（write_report）。

## 5. 创新点（含诚实负结果——这是特色）

**C2 参数自适应**（05 §C3 实验表，p6_full_bench::c2_selector）：逐张量
量化档位搜索，8 种配置 A/B 实测：

| 配置 | token 一致率 | 体积 | 判定 |
|---|---|---|---|
| default_q22 | 1.0000 | 474.7 MiB | P0 默认档 |
| **conv_fp16+emb_q22** | **1.0000** | **312.7 MiB（−34.1%）** | ✅ 收益点 |
| pure_int8 / adaptive / ladder_per_layer | 0.89 | ~268-460 | ✗ 诚实负结果：阈值判据失效、层级升级级联定型 |

解读："我们不是报一个最优点，而是把选择器为什么失效讲清楚——
一致率 1.000 的约束下只有两个合规点，自适应升级在此域退化。"

**C3 密文线性层双实现**：row-sum vs 对角线+gap-block+BSGS——row-sum 实测
慢 5.1×，负结果如实入库，选型决策有实验背书（src/model/ops/rowsum.py
即对照实现，保留在代码里供复核）。

## 6. 安全论证怎么做

- **威胁模型**（docs/02）：敌手能力表 + 假设核对表 A-1~A-9 + 攻击→机制→
  代码→测试四列表 + 半诚实模拟器简化论证；
- **攻击测试**（docs/03，自动化）：五类攻击 30 项判定 = 28 防御成功 +
  2 边界演示（模式 B t=2 合谋，预先声明）+ 0 失败；窃听=线缆全程密文 +
  运行时 0 命中扫描，中间人=SM2 证书双向认证拒，重放=会话 nonce/ratchet，
  篡改=审计链核验拒，合谋=边界如实声明；
- **审计防篡改**：SM3 哈希链（src/protocol/audit_log.py），P7-R1 补的
  4 线程×50 并发 append 用例（test_concurrent_append_200）把"锁是真的"
  变成可复跑交付物——这条曾因"声明与交付不符"被评审抓过，修复有档案。

## 7. 质量纪律体系（这个项目的"底座"）

1. **四检**：数据字典↔JSON / 注入表字节一致 / 过期值黑名单 / 文档互引，
   EXIT=0 才算文档与代码对账；
2. **D8**：数字一律脚本生成、JSON 权威、禁手抄；
3. **诚实档案**：P0/P1 各有《工作记录_附录》；每一次"声明与交付不符"
   （P6-R2 并发虚报、P7 微瑕）都修在明处并有修订对照表；
4. **验收表 F1~F10**：需求逐条映射到代码与测试（F2 明文扫描 / F3 认证 /
   F5 审计与密钥 / F8 运行时扫描 / F9 环境信息……）；
5. **复现**：`bash scripts/reproduce.sh` 干净目录 6 步一次通过
   （reproduce_logs/ 存证）。

## 8. 质量档案：声明与交付不符的处置

1. **P6-R2"声明与交付不符"**：记录声明"200 并发单测验证"但测试树没有
   该用例——评审判虚报轻量复发 → P7-R1 补 `test_concurrent_append_200`
   持久化用例（200 条 / seq 1..200 严格 / verify 全链），选择补交付物
   而非删声明；
2. **稳定性首跑 409 连锁**：PROVISION 阶段 status 请求偶发长卡顿
   （SEAL keygen GIL 尾部）导致连锁失败 → 确立"60s 容忍 + 失败路径必
   stop+等 idle"鲁棒性口径，并把 stall 作为证据记录而非隐藏；
3. **评审 G 项**：write_report 路径未归一 → 强制绝对路径归一化进 D8；
4. **演示冒烟竞态**：单节点双链路 establish 并发写审计日志 → 加锁修复
   + P7-R1 并发用例持久验证（同 1）。
